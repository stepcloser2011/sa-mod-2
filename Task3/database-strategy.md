**Обоснование**

1

Сервис ставок (Bidding Service)

Redis (для горячих данных) + Собственная БД не используется, используется Read Replica для БД в п 2

Redis нужен для сверхнизкой задержки (подгрузка правил аукциона, лимитов и пр) — критично для RTB

Используем Read Replica PostgreSQL сервиса рекламных кампаний используется для хранения неизменяемых правил кампаний, тарифов, историю ставок и служит источником истины. Такой подход даёт баланс скорости и консистентности.

2

Сервис кампаний (Campaign Service)

PostgreSQL

Данные о кампаниях — это транзакционные данные с жёсткими требованиями к целостности: статусы, бюджеты, расписания, таргетинги. PostgreSQL поддерживает ACID, сложные запросы по фильтрам и версионность изменений.

3

Сервис статистики

Stats Service)

ClickHouse

Статистика — это массивные потоки событий (показы, клики, конверсии) с агрегациями по времени, гео локацией и т. п. ClickHouse оптимизирован под быстрые аналитические запросы на больших объёмах и высокую скорость записи. PostgreSQL для данной задачи, здесь будет слишком медленным при росте нагрузки.

4

Сервис аналитики (Analytics Service)

ClickHouse

Аналитика строится на исторических данных и сложных агрегациях. ClickHouse обеспечивает высокую производительность при работе с временными рядами и большими датасетами.

5

Сервис финансов (Billing/Finance Service)

PostgreSQL (строгая изоляция + WAL/репликация)

Финансы требуют максимальной надёжности, строгой консистентности и возможности аудита всех изменений. PostgreSQL гарантирует ACID транзакции, и возможность восстановления до точки во времени.
